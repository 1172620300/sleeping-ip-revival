# Phase 1 角色与权限

## 两个独立维度

角色回答“账号是什么身份”，状态回答“账号目前是否可被授权”。不能仅因为角色是 `ADMIN` 就忽略 `PENDING`、`REJECTED` 或 `DISABLED`。

当前权限只覆盖 Phase 1 已交付入口。没有 AI、作品、材料、检测等未来业务权限，也没有账号审批写入功能。

## 状态矩阵

| 状态 | 登录 | 查看本人资料 | 获得角色特权 |
| --- | --- | --- | --- |
| `PENDING` | 允许 | 允许 | 不允许 |
| `APPROVED` | 允许 | 允许 | 按角色授权 |
| `REJECTED` | 允许 | 允许 | 不允许 |
| `DISABLED` | 不允许 | 不允许 | 不允许 |

账号已停用或从数据库删除时，旧会话不能继续访问受保护资源，因为服务端每次重新读取账号。

## 角色矩阵

下表中的角色权限以账号状态为 `APPROVED` 为前提；查看本人资料同时允许未停用的待审核/已驳回账号。

| 能力 | DESIGNER | STORE_OWNER | STAFF | ADMIN |
| --- | --- | --- | --- | --- |
| 登录、退出 | 是 | 是 | 是 | 是 |
| 查看本人账号及状态 | 是 | 是 | 是 | 是 |
| 查看其他账号的有限列表字段 | 否 | 否 | 否 | 是，只读 |
| 审核账号、修改角色/状态 | 未实现 | 未实现 | 未实现 | 未实现 |
| 访问未来业务模块 | 未实现 | 未实现 | 未实现 | 未实现 |

员工没有继承管理员权限。角色命名只表达 Demo 身份，不代表已确认真实员工岗位、组织或商业权限规则。

## 注册约束

- 只允许选择 `DESIGNER` / `STORE_OWNER`。
- 姓名、邮箱和密码由服务端验证；邮箱使用唯一约束避免并发重复注册。
- 新账号状态固定为 `PENDING`，客户端不能选择 `APPROVED`。
- 不能通过构造请求创建 `STAFF` 或 `ADMIN`。
- 密码最少 12 个字符，不超过 72 个 UTF-8 字节；只保存 bcrypt 哈希。
- 审核和员工/管理员创建流程本阶段不提供。演示中的已通过账号由 Seed 初始化。

## 服务端访问规则

| 入口 | 规则 |
| --- | --- |
| 首页、登录、注册 | 公开 |
| `/account` | 有有效会话，账号存在且未停用 |
| 当前账号 API | 仅返回会话对应的账号安全字段，未登录返回空用户 |
| `/admin` | 有有效会话，`role === ADMIN` 且 `status === APPROVED` |
| `GET /api/platform/users` | 同管理员页面；拒绝未认证和非授权账号，最多返回 100 条 |
| 登录/退出 | 使用 NextAuth 的会话与 CSRF 机制 |

管理员列表是 RBAC 的演示切片，不是完整后台。不能据此宣称已经有审核、停用、重置密码或修改角色功能。

## HTTP 与认证防护

注册入口要求 `application/json`，请求体最大 16 KiB，`Origin` 必须与 `NEXTAUTH_URL` 一致。输入 schema 严格拒绝未知字段，包括自带的 `status`。登录/退出使用 NextAuth 的 CSRF 机制。

注册成功返回 HTTP 201 `{ user }`；当前账号返回 `{ user }` 或 `{ user: null }`；管理员列表返回 `{ users }`。平台 API 错误统一为 `{ error, code }`，常见状态如下：

| HTTP | 代码 | 含义 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` / `INVALID_JSON` | 字段或 JSON 无效 |
| 401 | `UNAUTHENTICATED` | 未认证 |
| 403 | `INVALID_ORIGIN` / `ACCOUNT_NOT_APPROVED` / `FORBIDDEN` | 来源、账号状态或角色不允许 |
| 409 | `EMAIL_EXISTS` | 邮箱已注册 |
| 413 | `PAYLOAD_TOO_LARGE` | 请求体超限 |
| 415 | `CONTENT_TYPE` | 非 JSON 请求 |
| 429 | `RATE_LIMITED` | 触发本地限流 |
| 503 | `DATABASE_UNAVAILABLE` | 数据库未就绪 |

Credentials 登录失败对外统一为 `CredentialsSignin`，不区分未知邮箱、密码错误、停用状态或数据库故障细节。

当前限流保存在单进程内存：登录全局 80 次/分钟、单邮箱 8 次/15 分钟；注册全局 30 次/小时、单邮箱 3 次/小时。邮箱键数量有上限，应用重启会清空计数。这是本地 Demo 防护，不能替代生产分布式反滥用策略。

## 防止越权的实现约定

1. 会话只标识已认证账号，不把客户端角色作为权限来源。
2. 从数据库重新读取最新角色和状态，权限变化不等待 JWT 自然过期。
3. 普通账号查询绑定服务端会话 ID，不接受浏览器传来的目标用户 ID。
4. 管理员列表采用明确返回字段，永不返回密码哈希。
5. 每个受保护 API 都独立检查权限，不能仅依赖导航隐藏或页面重定向。

## 自动化验证要求

应覆盖未登录拒绝、各角色边界、待审核/已驳回受限、停用账号拒绝、注册提权拒绝、本人资料隔离、管理员只读列表和退出后的保护。测试结果以实际运行报告为准，不以本文中的测试要求代替验证。
