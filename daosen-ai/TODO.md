# Phase 1 默认值与待办

本文件区分已采用的开发默认值和未交付事项。当前阶段完成后停止，不自动推进 Phase 2 或完整 G0/G1。

## 已采用的合理默认值

- 技术栈固定为 Next.js App Router、TypeScript、Tailwind CSS、PostgreSQL 16、Prisma；不使用 SQLite 替代。
- 架构为模块化单体，一个应用和一个数据库；Phase 1 只启用账号与权限模块。
- 简体中文优先，桌面演示为主，保留基本移动布局。
- 单账号单角色，不建立租户、组织、门店成员或多角色模型。
- 公开注册仅支持 `DESIGNER`、`STORE_OWNER`，固定创建 `PENDING` 账号。
- `PENDING` / `REJECTED` 可登录查看本人资料，不能获得特权；`DISABLED` 禁止登录及受保护访问。
- `STAFF` 不自动拥有管理员权限。账号列表仅供 `APPROVED` 的 `ADMIN` 只读查看。
- 本阶段不提供状态/角色写入、审核或驳回重提流程，以演示种子账号覆盖不同状态。
- 本地认证采用邮箱+密码、NextAuth Credentials、8 小时 JWT 会话；密码使用 bcrypt 成本因子 12，最少 12 个字符且不超过 72 个 UTF-8 字节。
- 受保护请求重读数据库角色/状态；普通账号资料只按会话 ID 查询。
- Seed 使用七个虚构账号与公开演示密码 `Daosen@2026!`；只用于隔离的本地 Demo。
- Seed 需要 `ALLOW_DEMO_SEED=true` 显式启用；同邮箱已有用户不会被覆盖。初始迁移自带角色/状态字典，公开注册不依赖 Demo 账号 Seed。
- 无真实 AI、邮件、存储、支付或第三方账号调用；所需占位变量不代表已接入服务。
- 用户提供的旧 Vite / Supabase 源码仅供参考，不导入真实账号、业务数据、会话或第三方配置。
- 历史超出范围的业务草稿隔离在 `_future/`，不参与当前构建与交付。
