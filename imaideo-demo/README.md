# imaideo 经典 IP 共创平台演示版

这是一个独立的 React、TypeScript、Vite 项目，用于展示「大量 IP 资源 + 官方资产 + 创作征集 + AI 辅助制作 + 版权方审核」的完整产品表达。默认仍是本地演示；可选启动服务端代理接入 Seedance 视频 API，不会把密钥放进浏览器或提交到代码仓库，也不会修改 `imaideo.xyz`。

## 本地启动

需要 Node.js 20 或更高版本。

```powershell
npm install
npm run dev
```

访问 `http://127.0.0.1:4173/`。数据保存在当前浏览器的 IndexedDB 中；侧栏底部的「重置演示」可恢复预置数据。

## Seedance 2.0 接入

复制 `.env.example` 为 `.env`，在文件中填写沧元算力网关地址和 API Key。密钥只由 `server.mjs` 读取，不要粘贴到前端代码或提交到 Git。先启动代理，再启动 Vite：

```powershell
Copy-Item .env.example .env
# 编辑 .env，填写 CANGYUAN_API_KEY；模型名可留空，由服务端从 /v1/models 发现
npm run api
npm run dev
```

进入导演助手的「视频制作」步骤后，Seedance 面板会显示当前 token 可用的模型。选择模型、提交异步任务，再使用“查询任务状态”轮询结果。接入首次只提交模型和提示词，画幅、时长等字段需依据该 token 对应的 Seedance 模型文档确认后再扩展。没有 `.env` 或没有启动代理时，页面保留本地演示生成，不会发起外部任务。

编剧助手使用同一个服务端代理的 `/api/ai/writer`。按沧元算力的接入说明，填写 `CANGYUAN_BASE_URL`、`CANGYUAN_API_KEY`。多个文本模型用逗号分隔写入 `CANGYUAN_TEXT_MODELS`，例如 `gpt-5.5,gpt-5.6-sol,gpt-5.6-terra,gpt-6-astra,gpt-6-sol`；第一项同时作为默认模型，也可保留 `CANGYUAN_TEXT_MODEL` 指定默认值。编剧助手加载 `/api/ai/models` 后会显示下拉框，每次生成可选择其中一个模型；这表示按阶段切换模型，不会在一次请求中同时调用全部模型。视频模型单独填写 `CANGYUAN_VIDEO_MODEL`，当前示例为 `sd10-seedance-2.0`，导演助手的视频制作面板会从 `/v1/models` 读取并提交异步任务。当前 `.env` 使用 `AI_PROVIDER=openai-compatible`，未填写 `AI_*` 覆盖项时会复用 `CANGYUAN_*` 地址与密钥。可将 `AI_PROVIDER=mock` 离线验证；若需直连其他 OpenAI Compatible 服务，可用 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 覆盖。每一步会把前一步的已保存内容作为上下文，结果仍写回当前项目的 IndexedDB。

如果 `/v1/models` 没有返回配置的视频模型，接口仍会把 `CANGYUAN_VIDEO_MODEL` 标为“已配置 / 待授权”，便于先完成界面接入；真正提交前需要给当前 Key 开通 Seedance 权限，或换用能在模型列表中看到该视频模型的 Key。当前这枚 Key 的模型列表已确认包含上述 5 个文本模型，但没有返回 Seedance，因此视频模型暂时属于待授权状态。

如视频账号与文本账号不同，可在项目目录运行 `powershell -ExecutionPolicy Bypass -File .\configure-video.ps1`，在终端隐藏输入独立的视频 Key。脚本只写入本地 `.env` 的 `CANGYUAN_VIDEO_API_KEY`，视频请求会优先使用它；配置后重启 `npm run api`，再检查导演助手的视频模型列表。

```powershell
npm test
npm run build
npm run preview
```

生产构建输出在 `dist/`，可部署到支持静态站点和 SPA 回退的服务。路由使用 URL hash，因此普通静态文件服务也能直接运行。

## 约 5 分钟演示路线

1. 在首页说明平台关系：版权方提供 IP、资产与规则，创作者通过征集完成作品，版权方审核后进入展映。
2. 打开「一封迟到的信」，勾选规则并加入征集。
3. 在「编剧助手」编辑六类编剧资料并确认版本，点击「交给导演助手」；在导演区的「角色与资产」确认资产包。
4. 在「分镜设计」核对确认版剧本后确认分镜对应。在「视频制作」更新提示词、运行制作检查、生成镜头、播放分镜预演并提交 v1。
5. 切换为版权方，在「版权方中心」打开投稿，给某个镜头添加意见并退回。
6. 切回创作者，修改对应镜头、更新提示词并重新生成，提交 v2；版权方将 v2 设为入选，最后在「作品展映」查看结果。两个助手分别导出自己的 Markdown 资料；导演区顶部可导出含来源信息的项目 JSON。

刷新页面后，助手资料、投稿版本、审核记录和身份都会恢复。所有投稿保存独立快照，之后修改项目或版权方资料不会改写送审证据。独立画布仅展示固定示例，没有草稿保存功能。

## 演示边界

- 《天书奇谭》《九色鹿》《雪孩子》只作为「拟合作方向」展示，明确标注未获授权并禁止进入创作。
- 《云山邮局》《深蓝航线》《小城灯火》是本演示的原创示例世界。
- 「演示生成」返回预置结果；播放器是原创静帧、运动与字幕组成的分镜预演，不代表真实 AI 视频服务。
- 身份、激励、截止日期、任务发布和审核均为本地模拟，不产生真实交易或外部提交。

## 交付结构

- `src/App.tsx`：平台壳层与浏览页面
- `src/WriterStudio.tsx`：编剧工作区；`src/Studio.tsx`：导演制作与投稿；`src/CanvasDemo.tsx`：独立画布演示
- `src/Owner.tsx`：版权方任务、资产、投稿与审核
- `src/service.ts`：IndexedDB 与模拟业务服务
- `src/seed.ts`：演示数据
- `src/service.test.ts`：关键流程测试
- `public/assets/`：原创演示视觉
- `dist/`：可部署静态构建

素材来源见 `ASSETS.md`，视觉系统见 `DESIGN.md`。

## 编剧与导演助手

Short-Drama Factory 负责策划、人物、大纲、正文和连续性记录；漫剧老李工作流负责资产版本、分镜、提示词与制作检查。规则来源、固定提交号、许可与实际适配范围见 `skill-resources/README.md`。

`assistant-model.ts` 管理版本依据、失效状态、规则检查和资料导出；`assistant-service.ts` 提供本地编辑、确认和检查操作；`assistant-samples.ts` 保留兼容旧项目所需的基础资料。既有 IndexedDB 数据无需重置；旧投稿不被迁移或覆盖。

助手界面已移除预置示例标签、载入示例按钮和失败体验入口。上游变更仍会保留文字并使下游状态过期；Seedance/H3 仅作为提示词格式选项。制作配置中的画幅不会裁切现有横屏预演素材。

后续真实接入需替换：编剧和分镜的文本模型服务、资产图像服务、视频生成与任务队列、服务端项目及媒体存储；模型密钥仅保存在后端。另需真实账户与权限、费用预算、内容审核和实际模型参数验证。本次没有新增生产 API、登录或付费服务。

## 独立创作分区

- “开始创作”进入“我的项目”。左侧“我的项目”展开“编剧助手”和“导演助手”，项目页也提供两个板块入口。
- “编剧助手”：选择项目，完成策划、人物、大纲、正文与连续性记录，检查并确认版本后点击“交给导演助手”。仅导出编剧资料。
- “导演助手”：只读接收已确认剧本，按资产、分镜、视频制作、投稿四个步骤继续。修改剧本需返回编剧助手；上游变更保留制作内容并提示更新。
- 左侧“画布创作”：独立自由创作的静态演示布局，不读取项目，不实现拖动、编辑、生成或草稿保存。旧项目的画布坐标和缩放字段仍保留，不再嵌入助手界面。
- 项目链接为 `#/assistants/writer/:id` 和 `#/assistants/director/:id`。旧 `#/studio/:id` 链接继续兼容，草稿进入编剧，其他状态进入导演；旧 assistant 参数仍优先决定分区。
- 编剧检查与导演检查独立保存，投稿检查仍覆盖完整链路。只读状态可浏览即时检查结果，但不能保存检查记录或修改确认版本。

当前所有生成能力仍为本地模拟；真实画布服务、文本/图像/视频服务、后端鉴权、队列、文件存储、用量统计和成本控制均留待后续接入。
